# 집짓기 시제품 (Three.js 웹판)

생활형 협동 RPG의 첫 단계인 집 꾸미기 시제품입니다. 짓는 방식은 동물의 숲을 따릅니다. 정해진 집을 갖고, 키우고, 겉모습을 고르고, 문으로 들어가 방을 꾸밉니다.

## 실행

```bash
npm install
```

```bash
npm run serve
```

브라우저에서 `http://localhost:5173` 을 엽니다. `index.html` 을 더블클릭해서는 열리지 않습니다 (모듈 스크립트는 서버를 거쳐야 합니다). Node.js 가 없고 Python 이 있으면 이 폴더에서 `python -m http.server 5173` 으로도 열 수 있습니다.

GitHub Pages 에는 이 폴더를 그대로 올리면 됩니다. three.js 는 실행할 때 CDN 에서 불러오므로 `node_modules` 는 올리지 않아도 됩니다.

## 들어 있는 것

- 마당과 방. 마당에는 집의 겉모습이 서 있고, 집을 누르거나 문으로 걸어가면 방 화면으로 바뀝니다
- 집 키우기 세 단계. 방이 6×6칸에서 10×10칸까지 넓어지고 겉모습도 커집니다
- 겉모습 고르기 (지붕, 외벽, 문의 색), 방 꾸미기 (바닥재, 벽지)
- 가구 15종을 방과 마당에 놓기, 돌리기, 옮기기, 치우기
- 올려놓는 소품 5종. 탁자, 수납장, 서랍장 위에 놓습니다. 가구를 옮기거나 돌리면 위의 소품이 따라가고, 가구를 치우면 함께 치워집니다
- 벽에 거는 것 6종 (액자와 선반). 방의 벽에 겁니다. 창문과 문 자리에는 걸 수 없습니다. 카메라 쪽 벽에 건 것은 카메라를 돌려야 보입니다
- 캐릭터 걷기 (키와 누르기), 가구 충돌, 90도씩 도는 카메라, 확대와 축소
- 되돌리기와 다시 하기 (Ctrl+Z, Ctrl+Shift+Z, 꾸미기 모드의 버튼)
- 자동 저장. 바뀔 때마다 브라우저(localStorage)에 저장하고 다시 열면 이어집니다. 저장은 브라우저와 주소마다 따로입니다
- 집 공유. 위쪽 **집 공유** 버튼으로 지금 꾸민 집의 배치를 링크에 담아 보내면 친구가 읽기 전용으로 구경합니다. 서버를 쓰지 않으며, **구경만 할 때는** 친구의 저장된 집이 바뀌지 않습니다. **내 집으로** 버튼으로 돌아옵니다. 집을 바꾼 뒤에는 새 링크를 만들어야 합니다
- **다른 브라우저로 집 복사:** 기존 집에서 **집 공유** 링크를 보관한 뒤 새 브라우저에서 열면 **집 가져오기**가 나타납니다. 확인하면 기존 브라우저의 저장 집은 건드리지 않고, **새 브라우저에 원래 있던 집을 따로 보관**한 뒤 링크의 배치를 그 브라우저의 개인 집으로 복사합니다. 새 브라우저의 **집 공유 → 보관된 다른 집과 맞바꾸기**를 누르면 지금 집도 따로 남긴 채 두 집을 번갈아 사용할 수 있습니다. 한 번에 보관하는 다른 집은 하나이며, 그 상태에서 또 다른 링크의 집을 바로 가져올 수는 없습니다. **가져오기 전 새 브라우저에 저장된 집이 없었다면 맞바꾸기 버튼은 나타나지 않습니다.** 다른 탭에서 집이 변경되면 오래된 탭의 자동 저장을 중단하고 다시 열도록 안내합니다. 이 기능은 **Firebase 익명 계정, 온라인 집 소유권, 방명록은 옮기지 않습니다.**

  - Claude 임시 게시 화면에서 눌러도 링크의 주소는 항상 **GitHub Pages 정식 배포 주소**를 사용합니다. 공유 기능 PR을 병합하고 Pages에 반영한 뒤에 링크를 시험해야 합니다.
- 휴대폰 터치 조작. 가구는 누른 채 자리를 고르고 떼면 놓입니다. 끌어서 옮기고, 두 손가락으로 확대합니다. 키가 하던 일은 모두 버튼으로도 됩니다

## 구조

| 파일 | 맡은 일 |
|---|---|
| `src/parts.js` | 가구, 바닥재, 벽지, 겉모습 색, 집의 단계 (자료만) |
| `src/state.js` | 규칙. 모든 변경은 명령으로 처리하고 가구마다 고유 ID 를 붙입니다. three.js 를 쓰지 않습니다 |
| `src/history.js` | 되돌리기. 명령마다 반대 명령을 기록하고, 되돌릴 때 다시 검증합니다 |
| `src/save.js` | 저장과 불러오기. 저장 형식 버전과 변환 자리가 여기 있습니다 |
| `src/online.js`, `src/online-service.js`, `src/online-data.js`, `src/online-ui.js` | Firebase 온라인 공유(선택), 익명 로그인, 방문 인사, 모바일 대화창 |
| `firestore.rules` | Firestore 집 공개·방명록 보안 규칙 |
| `src/sample.js` | 처음 놓여 있는 가구 |
| `src/view.js` | 화면. 마당의 집과 방을 그리고 카메라를 다룹니다 |
| `src/input.js` | 조작. 포인터와 키 입력을 명령으로 바꿉니다 |
| `src/character.js` | 걷기, 충돌, 길 찾기 |
| `src/ui.js`, `src/main.js`, `page.html` | 도구 목록과 버튼, 시작, 마당과 방 오가기 |
| `tools/pack-models.mjs` | glTF 모델을 `assets/models.json` 하나로 묶습니다 |

`page.html` 이 화면 본문이고 `index.html` 은 그것을 감싼 파일입니다. `page.html` 을 고친 뒤에는 `npm run index` 를 실행합니다.

## 가구 추가

1. 모델 파일(`.gltf`, `.bin`)과 함께 받은 텍스처(`.png`)를 `assets-src/furniture/` 에 넣습니다. 나눠 준 사본에는 원본 모델이 빠져 있지만, 이미 쓰는 모델은 묶어 둔 것을 그대로 쓰므로 새 모델만 넣으면 됩니다. `.glb` 파일은 아직 읽지 못합니다.
2. `src/parts.js` 의 `PARTS` 에 한 줄을 더합니다. 예: `bench: { label: '낮은 탁자', size: [3, 2], model: 'furniture/table_low' }`
3. `npm run pack` 을 실행합니다. 모델의 크기가 표로 나오므로 칸에 맞는지 확인합니다. 한 칸은 1 단위이고 의자 하나 크기입니다.

놓이는 자리는 `layer` 로 정합니다. 적지 않으면 바닥의 가구, `'rug'` 는 가구 아래, `'top'` 은 가구 위의 소품, `'wall'` 은 벽에 거는 것입니다. 소품을 받칠 가구에는 윗면 높이 `surface` 를, 벽에 거는 것에는 차지하는 벽 칸 수 `span` 과 높이 `hang` 을 적습니다.

앉을 수 있는 가구에는 `seat` 를 적습니다. `h` 는 앉는 면의 높이, `z` 는 앉는 자리가 가운데에서 앞으로 나온 거리, `x` 는 자리가 여럿일 때의 좌우 위치입니다.

모델이 칸 가운데에서 어긋나면 `offset`, 크기가 안 맞으면 `scale` 을 그 줄에 적습니다. 바닥재, 벽지, 지붕 색도 같은 파일의 목록에 한 줄을 더하면 보기에 나타납니다.

## 확인

```bash
npm test
```

규칙, 되돌리기, 저장 테스트입니다. 공유 링크 변환·손상 복구 테스트(`test/share.test.mjs`), 집 복사·양방향 교환·비정상 종료 복구·다른 탭 충돌 차단 시험(`test/house-transfer.test.mjs`)도 포함됩니다. 화면 확인은 서버를 띄운 채 `node tools/shot.mjs / 출력이름 1280 800 test/tour.mjs` 로 자동 둘러보기를 돌립니다. 소품과 벽걸이는 `test/decor.mjs` 로 같은 방식으로 확인합니다. 터치 조작은 `TOUCH=1 node tools/shot.mjs / 출력이름 390 844 test/touch.mjs` 로 확인합니다. 의자에 앉기는 `test/sit.mjs` 를 두 방식 모두로 돌립니다(마우스는 `1280 800`, 터치는 `TOUCH=1` 과 `390 844`).
집 공유 브라우저 시험은 서버를 띄운 채 `node tools/shot.mjs / shots/share 390 844 test/share.mjs` 로 실행합니다. 같은 탭 공유 링크 전환, 조작된 링크, 원래 집 저장 보호를 확인합니다.
집을 다른 브라우저로 가져오고 두 집을 맞바꾸는 모바일 시험은 `test/house-transfer.mjs`, 오래된 다른 탭의 자동 저장을 차단하는 시험은 `test/house-transfer-tabs.mjs`로 실행합니다.
온라인 창은 같은 방식으로 `test/online.mjs`(가짜 서비스로 게시, 방명록, 방문 인사)와 `test/online-timeout.mjs`(서버가 응답하지 않을 때 창이 닫히는지, 방문 링크가 내 집으로 넘어가는지)로 확인합니다. 둘 다 `TOUCH=1` 과 `390 844` 로 돌리며 실제 Firebase 에는 접속하지 않습니다.

## 다음 단계: 친구의 흔적 저장

**Firebase 온라인 집 게시와 방명록은 실제 GitHub Pages에서 동작하며 사용자가 휴대폰에서 확인했습니다.** 다만 현재는 Firebase 익명 계정이므로 브라우저마다 서로 다른 온라인 집주인 UID를 사용할 수 있습니다. `#home=` 집 복사는 로컬 가구 배치만 옮기는 기능이지 온라인 집 소유권이나 방명록을 합치는 기능이 아닙니다. 이 부분을 해결하려면 별도로 안전한 계정 연동과 소유권 복구 절차가 필요합니다.

온라인 보안 규칙과 시험 절차는 `docs/ONLINE_STORAGE_PLAN.md`를 참고합니다. 비밀번호나 서비스 계정 비밀 키를 공개 저장소에 올리지 않습니다.
