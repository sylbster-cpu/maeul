# 7단계 공동 쉼터 — 첫 기술 계약

2026-11-27 사용자 결정(공동 이슈 #4 글 161)과 휴대폰 인수 확인에 따른 구현. 이 초안 PR은 규칙·저장·명령·부정 시험 기반, 별도 조작 체험, 온라인 입장·초대·재접속·저장 연결을 다룬다. 운영 규칙 배포와 실기기 확인은 아직 하지 않는다.

- 질문: 친구의 흔적을 보고 스스로 다시 와서 내 행동으로 그 풍경에 응답하는가.
- 확정 범위: 별도의 8×8 장면, 최대 4명, 1인 6개, 이동/회전/치우기, 지난 방문 이후 친구가 바꾼 물건을 은은하게 표시. 실시간 캐릭터 동기화나 보상 없음.
- 배치 후보는 기존 1×1 모델 stool, side_table, plant, lamp. 입구 쪽 3_0, 4_0, 3_1, 4_1은 통로로 비운다(구현 기본값; 장면 검토 때 좌표와 함께 확인).
- 이 문서의 실제 저장 방식은 초기 다문서 후보에서 **쉼터 하나당 단일 문서**로 좁혔다. 최대 24개이므로 작은 상태를 한 트랜잭션으로 검증·쓰기 쉽고 문서 간 불일치 및 getAfter 호출 한도를 피한다. 대규모 실시간 공간으로 확장하는 사양이 아니다.

## 저장 구조

`shelters/{자동 생성 20자 ID}`: version=1, ownerUid, members(고정 표식 tree/wind/star/moon → UID), items(표식 → 고정 슬롯 0..5 → {kind,cell,rot}), cells(칸 → {mark,slot}), revision, change, updatedAt. 셀은 x_y 형식. 단일 문서에 이중 점유가 생기지 않게 규칙이 매 명령 전이를 검사한다. 개설/참여/빈 자기 표식 나가기/놓기/이동/회전/치우기 외 전이는 거부. 다른 표식·슬롯·칸에 영향을 주는 쓰기는 거부. 판 번호는 한 번씩 증가하며 시각은 서버 시각이다.

인증된 사용자가 추측하기 어려운 초대 주소를 알면 단건 읽기와 참여 가능, 전체 목록 조회 및 문서 삭제 불가. 이 링크 자체가 초대 권한이므로 공개 게시를 피해야 한다. 표식의 실제 소유자는 Firebase UID다. 내 UID는 한 자리만 쓸 수 있다. 소유권을 다른 브라우저로 옮기는 기능은 이번 범위가 아니다. 다른 브라우저의 UID를 되찾을 수 없고 가구가 남은 표식은 비울 수 없는 문제가 있다. 개설자의 타인 가구 강제 삭제는 사용자 승인 없이 넣지 않는다. 화면 연결 시 같은 일반 브라우저 사용 안내, 내 표식 표시, 비어 있는 자기 표식 반환 경로를 검토하고 계정 분실 대책은 사용자 결정으로 남긴다.

## 클라이언트

`src/shelter-state.js`: 순수 검증→적용→반대 명령, 수신 상태 검사. `src/shelter-service.js`: Firebase API 주입, 최신 읽기와 트랜잭션. 화면에서 저장된 상태를 직접 수정하지 않으며, 이동/회전/삭제 명령에는 화면에서 본 기존 가구를 담는다. 동시 변경 시 같은 명령을 최신 상태로 다시 검증하고 이미 점유된 칸이나 바뀐 가구는 거절한다. 에뮬레이터에서 동시 쓰기의 판 번호 검사로 permission-denied가 발생하고 SDK가 재시도하지 않는 경로를 Claude가 재현했다. 서버를 다시 읽어 판 번호가 증가했을 때만 최신 상태를 검증하고 최대 세 번 시도한다. 실제 권한 오류는 숨기지 않으며, 겹친 칸/낡은 가구/가득 찬 쉼터는 규칙의 오류를 돌려준다. 쓰기 성공 전 상태를 낙관적으로 확정하지 않는다. 운영 집/낚시/채집 데이터와 무관. 재방문 변화는 별도 UID/쉼터 주소 키에 마지막으로 표시한 서버 상태를 기억하여 비교한다. 2026-11-27 사용자가 Claude에게 예외적으로 수정하도록 허락한 커밋 ba3fc47을 2026-11-28 GPT PR에 그대로 인수했다. 접속 중 및 숨긴 탭 복귀, 내 저장 응답에 섞여 온 친구 변경도 이전 판과 비교해 표시를 합친 뒤 기억한다. Claude 사본의 단위 176·온라인 15·조작 체험 14 시험은 통과했으나 최신 PR CI와 실제 휴대폰은 별개다. 배경 탭의 새 상태는 보이는 화면으로 돌아올 때 적용하고, 캐시나 미확정 쓰기는 서버 판으로 취급하지 않는다.

## 독립 조작 체험 (추가 구현)

`shelter.html`은 별도 8×8 숲 쉼터. 기존 1×1 가구 모델과 캐릭터를 재사용하고, `shelter-projection.js`가 쉼터 점유를 캐릭터 충돌 자료로만 변환한다. `shelter-preview.js`는 메모리의 두 명 예제 상태만 검증→적용하며 집·낚시·채집·Firebase·localStorage에 접근하지 않는다. 바닥을 누르면 걷고, 꾸미기 목록에서 골라 연속 배치하며, 내 가구만 골라 회전·이동·치우기·완료. 다른 표식의 물건을 누르면 주인을 알려 준다. 입구는 보호하며, 이전에 본 가구 대비 새로 배치된 친구 가구에 7.5초 동안 바닥 고리와 작은 빛을 표시하고 서서히 사라지게 한다. Claude가 54afccc의 360×640 화면에서 기존 고리가 너무 희미하다고 확인하여 넓혔고, 칸을 누르기 쉽게 카메라를 조금 더 내려다보게 했다. 수정 후 실제 화면은 재검증 필요. 이 체험판은 재접속 저장/초대/실시간 동기화를 검증하지 않는다. 체험 주소는 `shelter.html?preview=1`이다. 실제 입장은 아래 별도 경로를 사용한다.

## 실제 입장과 저장

`shelter.html`에서 익명 인증 후 새 쉼터 만들기 또는 마지막 쉼터로 돌아가기. `shelter.html#room=ID`는 주소만 읽고 명시적인 참여 버튼을 눌러야 슬롯을 차지한다. 이미 회원이면 같은 표식으로 들어간다. 초대 복사는 정식 Pages URL을 사용한다. 생성 요청은 미리 만든 같은 ID로 재시도하며 기존 타인의 문서를 덮지 않는다. 서버 확인 상태만 화면에 반영하고 진행 중에는 중복 편집을 막는다. 구독은 확정된 서버 판만 사용하고 오래된 판을 무시한다. 연결이 끊기면 꾸미기를 중지하고 다시 읽기를 제공한다. 실제 친구의 배치는 반영하되 캐릭터 실시간 동기화는 하지 않는다. 친구 배치가 바뀌면 가던 자리까지 최신 점유에서 길을 다시 찾는다. 마지막 주소/재방문 기억은 별도 `maeul:shelter:` 키만 사용한다. 계정 분실 복구·타인 강제 제거는 미정이며 참여 전 같은 일반 브라우저 사용을 안내한다. 마을 ☰ 메뉴의 공동 쉼터 버튼으로 들어간다. 내 집의 저장이 실패하면 이동하지 않고 알려 준다. 방문 중인 집에서는 이 버튼을 숨긴다.

## 검증

단위시험은 `npm test`, 서버 규칙은 기존 Firebase 에뮬레이터 CI로 확인한다. 실제 서버 게시와 실기기 시험은 이 PR에서 하지 않는다. 브라우저와 CLI 네트워크가 없는 GPT 환경에서 전체 저장소를 직접 실행할 수 없으므로 draft PR CI로 확인하며 통과 전 병합 권고하지 않는다. 이후 장면/모바일 조작/초대 경로를 연결한 뒤 두 휴대폰에서 초대, 교대 배치, 다시 접속, 타인 소유권, 동시 충돌을 직접 확인한다. 사흘 자발적 재방문 관찰은 조작 테스트와 구분한다.
